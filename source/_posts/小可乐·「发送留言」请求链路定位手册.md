## 1. 一句话原理（先讲通整件事）

把「发一条留言」想成**寄快递**：

| 现实 | 代码里 |
|---|---|
| 你按下"寄出"按钮 | `onClick` 触发 |
| 把手里的东西装进一个**快递单**（收件视频、内容、@了谁） | `ClickPublishParams`（混淆名 `C1HQW`） |
| 交给**前台柜台** | `C1HMS.LIZJ()` |
| 柜台转给**发货部门** | `PublishAbility.Ao1()` → `PublishPresenter` |
| 发货部门**打包成标准包裹**（表单字段） | `CommentPublishRequest` |
| 交给**快递公司**（真正上网） | `CommentRealApi` → `POST /aweme/v1/comment/publish/` |

每一层都只是"往下交"，**真正的 URL 只在最后一层**。所以找数据包的正确姿势是：**从按钮往下追，一直追到 `@POST` 那一行**。

## 8. 坑清单（现象 → 原因 → 修法）

| 现象 | 原因 | 怎么修 |
|---|---|---|
| 全量 `grep` 返回空，但旧目录能搜到 | jadx 是**分批写文件**的，那个类还没写到磁盘（进度 82% 时缺后 18%） | 先 `find` 确认文件在不在；不在就等，或换已完成的目录 |
| `ERROR - finished with errors, count: 1301` 且进度停在 82% | 56 个 dex / 38 万个类，巨型工程中途报错退出，**不是**"跑完了" | 用之前单独反编译的 `classes33/sources` 补齐；或按单个 dex 分别反编译 |
| 反编译产物不见了 | `/tmp` 在 macOS 重启时会被清空 | 产物放 `~/Desktop/android/`，APK 也一起搬 |
| 以为 `PublishBtnViewModel.Wb0` 是按钮入口 | `Wb0` 参数是来源标记，被键盘发送键/表情面板调用 | 见文首对照表；屏幕按钮的真实类**尚未证实**（见 12.3） |
| `grep` 6 分钟没输出 | 1.4G / 31 万个文件在 macOS 上较慢 | 先按目录或接口名收窄，别一上来全量搜 |
| LSPosed 模块装好了但一条日志都没有 | **重装 APK 后模块记录是新的 `enabled=0`、`scope` 为空**（旧记录随卸载一起删除） | 进 LSPosed 管理器：模块 → 打开「启用模块」→ 勾选目标应用；或直接读 `/data/adb/lspd/config/modules_config.db` 的 `modules.enabled` 与 `scope` 表核实 |
| 模块已启用，钩子仍 0 命中，误判为"App 反 Hook" | 用 `Activity.onResume` / `TextView.setText` 当探针 —— **子类会覆盖父类方法**（`SplashActivity`、`AppCompatTextView`），钩父类收不到 | 用**静态方法**或 App 自己的类做探针（本次用 `com.bytedance.memoryx.StringBuilderCache.get`，命中即证明钩子生效） |
| 挂上钩子后 App 卡在启动图（CPU 70%+、主线程空转） | 钩了**极高频方法**当探针（`StringBuilderCache.get` 每秒上万次），Xposed 调用开销把启动拖死 | 探针只选"每次启动几次"的方法（如 `Instrumentation.callApplicationOnCreate`）；业务钩子选低频方法 |
| 设备重启后 LSPosed 报 `DeadSystemException`、注入失效 | `system_server` 崩过一次，`lspd` 状态失效 | 重启手机重建环境 |
| 手机无 WiFi 时 App 卡在 `SplashActivity` | 启动强依赖网络；无 SIM、无 WiFi 时完全不可用 | USB 反向供网（gnirehtet）或接热点；重启后记得重跑并确认 VPN 授权弹窗 |
| `X.C1HQW` 用 `findClass("X.C1HQW", cl)` 找不到 | 该类可能由 App 内部类加载器加载，不在 zip 顶层 ClassLoader 视野内 | 改成"先命中 `YR`，再用 `param.args[3].getClass()` 取真实类"再反射 |
