## 一、基础：HTTPS 和证书是什么

### Q1：HTTPS 和 HTTP 差在哪？

- **HTTP = 明信片**：内容写在信封外面，路上谁都能偷看、篡改
- **HTTPS = 带锁保险箱**：只有收件人能拆

但保险箱带来新问题：怎么确认对面真是"某音总部"而不是骗子？——这就需要**证书**。

### Q2：证书到底是什么？

> **证书 = 服务器的"防伪营业执照"**，由全球公认的权威机构（CA，可理解为官方公证处）盖章签发。

一张证书里装着：

```
┌─────────────────────────────────┐
│ 正文（明文，人人可读）：              │
│   名字 = *.douyin.com             │
│   某音的公钥 = KKKK                │
│   有效期 / 序列号 / 发证方...        │
├─────────────────────────────────┤
│ 签名盒：CA用自己私钥锁进来的指纹      │ ← 防伪部分
└─────────────────────────────────┘
```

### Q3：证书的目的是什么？

一句话：**由权威机构担保，把「网站身份」和「网站公钥」焊在一起。**

两件事缺一不可：
- 只有加密、没验身份 → 你跟假某音加密聊得火热，钥匙给骗子了 😱
- 只验身份、没拿公钥 → 知道他是真人，但没钥匙没法安全通话

## 二、验证流程：指纹 A 和指纹 B

### Q4：手机怎么验证证书真假？（核心流程）

三方手里的东西：

| 角色 | 手里的东西 | 干嘛用 |
|---|---|---|
| 某音服务器 | 自己的私钥（绝不外传）+ 证书 | 出示证书、证明"我是本人" |
| CA 厂家 | 自己的私钥（核弹级保管） | 给别人的证书盖章 |
| 你的手机 | 系统名录里所有 CA 的**公钥** | 验章 |

### Q5：指纹机（哈希）是什么？

一台公开的数学机器（如 SHA-256），特性：
- 同样内容 → 同样指纹
- 内容差一个空格 → 指纹天差地别
- **单向**：从指纹拼不回原文（像苹果榨成汁回不去）

它**不算加密**：没有钥匙、不可逆、人人可算。三件套区别：

| 工具 | 钥匙 | 可逆 | 用途 |
|---|---|---|---|
| 指纹机（哈希） | 无 | ❌ | 算内容快照，验篡改 |
| 加密 | 收件人公钥 | ✅ 私钥解 | 保密 |
| 签名 | 自己的私钥 | ✅ 公钥验 | 防伪 |

### Q6：指纹 A 和 B 分别是怎么来的？

**A = 厂家当年封存的快照**
```
盖章那天：证书正文 ──指纹机──▶ a3f9...c3 ──厂家私钥锁盒──▶ 签名
```

**B = 手机现场重算的快照**
```
验货这天：手里的正文（服务器刚发来的）──同一台指纹机──▶ a3f9...c3
```

- 指纹机的公式是全球统一标准，浏览器出厂内置，不需要向任何人要
- 正文的材料也在手边——证书本来就是明文寄过来的
- **A == B → 内容没被改过、且真是官方发的 ✅**

> 🍎 比方：果园发货贴火漆封的重量单"10kg"（A）；你收到后自己上公平秤再称一遍（B）。对不上 = 中途动过手脚。

### Q7：指纹机算的是哪些数据？

**就是证书正文的全部公开信息，一字不差**——名字、公钥、有效期、序列号……全喂进去。

> 为什么公开信息也锁？锁的目的从来不是"藏"，是"封存快照"。像合同的骑缝章：内容本来就公开，但盖了章之后谁改一个字都能发现。
>
> 设计规则：凡是不想被人偷改的字段，一个都不能漏在指纹外。（假如只锁名字没锁公钥，骗子就能换掉公钥搞中间人攻击！）

注意：签名盒子本身不参与算指纹（不然死循环）。

## 三、信任链：那么多证书，怎么知道用哪个？

### Q8：系统里一百多张根证书，App 怎么挑？

**App 从来不是"挑"，而是"顺藤摸瓜往上爬"。**

证书体系是一层扣一层的连环保：

```
【根证书】GlobalSign 总公证处        ← 在手机系统名录里 ✅
    ↓ 授权并担保
【中级机构】GlobalSign 中国分部
    ↓ 签发给
【某音的证书】*.douyin.com           ← 服务器递来的这张
```

手机拿到证书后逐层问"这是谁签发的？"，用上一级的公钥验下一级的签名，一路爬到头，只要撞见系统名录里的根 → 放行。

> 🎓 比方：收到毕业证 → 大学盖章 → 办学资格有教育厅批文 → 教育厅在你心里的官方名单上。链条爬到名单里的人就收下。

### Q9：厂家的公钥到底在哪里？

**就在手机系统文件夹里，出厂预装！**

```
/system/etc/security/cacerts/
├── 6d99fb26.0   ← 每个文件 = 一家 CA 的根证书（内含它的公钥）
├── ...
└── (~140 个文件)
```

我们抓包前往这里塞过 mitmproxy 的证书——就是亲手体验了这个机制。

这些根证书**不是上网下载的**（否则半路会被骗子掉包，信任链塌方），而是：
1. Google/Apple 造系统时审核后焊死在镜像里
2. 通过系统更新增删（作恶的 CA 会被除名，如 2011 年 DigiNotar 被黑客偷私钥后全网除名、公司破产）

> 🏭 验钞机出厂时机芯就刻好了人民币防伪特征——信任必须有个**离线的起点**，那就是手机出厂那一刻。

### Q10：骗子把"发证方"涂改成 GlobalSign 不就行了？

不行！"发证方"三个字**不是给你看的，是给你验的**：

> 你在栏里写谁的名字，手机就真拿谁的公钥来试开你的签名盒。

三条路全死：

| 作弊手法 | 死因 |
|---|---|
| 只改名 | 正文变了 → 指纹 B 变 → A≠B ❌ |
| 改名+找张三重新签 | 张三私钥锁的盒，GlobalSign 公钥开不开 ❌ |
| 自己当根自签 | 爬到头发现系统名录没你这家 ❌ |

> 🔑 核心：链条不是靠"写字"串起来的，是靠数学签名焊死的。你可以吹"我爸是李刚"，但你得拿出李刚私钥盖的章。

## 四、常见误解逐一纠正

### Q11：「手机用厂家公钥解密证书，才得到某音的文字和公钥」？

❌ 反了。**证书从头到尾是明文，内容直接读，零门槛。**

厂家公钥只用来干一件事：打开签名盒取**指纹 A**（取出来的是一小段指纹，不是正文！）。

| 步骤 | 动作 | 要钥匙吗 |
|---|---|---|
| 读正文（名字/公钥/有效期） | 直接读 | 不要 |
| 算指纹 B | 喂指纹机 | 不要 |
| 开签名盒取 A | **要厂家公钥** | ✅ |
| 对比 A==B | —— | —— |

> 证书像墙上挂的营业执照：不怕看，怕仿造。所以功夫全在"章仿不出来"，而不是把内容藏起来。
>
> 验章不产生新信息，产生的是**信任**——钢印不会让成绩单分数变多，只是让你敢信它。

### Q12：「指纹是用私钥加密的吧」？

✅ 对！RSA 这类算法里，这个动作确实和加密是同一套运算。

之前纠正的是另一件事：加密的对象是**指纹**，不是整张证书。

行话叫"签名"而不叫"私钥加密"，因为目的相反：
- 加密 = 藏（用**收件人**公钥）
- 签名 = 证（用**自己**私钥，生怕别人不知道是我发的）

> 把文件锁保险箱 = 加密；按手印/盖火漆 = 签名。

### Q13：「指纹机对信息加密 → 厂家私钥再加密一次 → 形成证书」？

顺序对了，但最后差半步：**正文不能丢，得原样留着！**

```
证书 = 【明文正文，原封不动】 + 【签名盒】
```

两个硬理由：
1. 指纹单向不可逆，只存指纹的话名字和公钥的信息永久消失
2. App 验证通过后要用读出来的公钥干活

> 毕业证不能只印一个钢印编号不印姓名——钢印是对着文字盖的，但**不能取代**文字。指纹是正文的"贴身保镖"，不是"替身"。

## 五、代理怎么看到 HTTPS 内容（中间人攻击）

### Q14：代理凭什么能拆开加密的信？

mitmproxy 耍两面派（MITM 中间人）：

```
原来：  手机 ←———— 一条加密隧道 ————→ 某音      （代理插不进手）

现在：  手机 ←— 加密隧道A —→ 代理 ←— 加密隧道B —→ 某音
              （假证书）         （真证书）
```

- 对手机：冒充某音，现做假证书（名字写某音，章是 mitmproxy 自己刻的）
- 对某音：冒充手机，另建一条正常隧道

代理是两条隧道的交汇点，两边明文都从它手里过。**它没有破解加密，而是让双方都在跟"它"加密。**

### Q15：手机为什么会认假证书？

因为我们做了这一步（需要 root）：

```bash
su -c 'cp mitmproxy证书 /system/etc/security/cacerts/'
```

= 把代理私刻的公章**偷偷加进了官方名录**。手机一验："章在册，放行 ✅"

> 这也解释了为什么要 root 才能玩转抓包：普通途径根本摸不到那个文件夹——这正是绝大多数正常人对中间人攻击免疫的原因。

## 六、某音为什么不认？——SSL Pinning（证书锁定）

### Q16：普通 App vs 某音的区别

| 类型 | 验证逻辑 | 结果 |
|---|---|---|
| 大多数 App | 只走系统标准安检门（链条能爬到名录即可） | 装 mitmproxy 证书后直接可抓 ✅ |
| 某音 | 标准安检 + 自家保安复核编号 | 必须上 frida 🔧 |

普通 App 判断标准就一条：**章能不能爬到系统名录里的某一家**。"正规"不看名气，看"在不在册"。

某音则把自家证书的编号（SHA-256 指纹）**焊死在 App 内部**，每次握手人工复核：

> 标准安检过了也没用，保安说："掏出证书跟我内部名单对一下"——对不上就翻脸（日志里的 `certificate_unknown` 警报就是这么刷屏的）。

> 🏦 比方：前台看你工牌是真的就放你进大楼（普通 App）；金库大门不看工牌，要对暗号（Pinning）。

### Q17：那最后怎么绕过的？

用 frida 当"内鬼"，在某音运行时动手脚：
1. hook `SSL_new` 从源头关掉校验开关
2. hook 取证书的函数，让它永远返回真某音证书给核对员看

核对员一看编号一致 → 放行 → 明文到手。

（后来 feed 还是刷不出来是另一个关卡：服务器风控嫌设备签名不对，故意不给数据——跟证书无关了。）

## 七、延伸：钓鱼网站怎么防？

证书证明"它是它"，不代表"它是好人"——钓鱼站也能花几块钱买正经证书、显示绿锁 🔒。

### 三层防线

**① 你自己（最重要）：认门牌**
- 域名**从右往左读**：`pay.bank.com.security-check.cn` 的主人是 `security-check.cn`，`bank.com` 只是装饰品
- 规则一条：**倒数第二段+后缀 = 主人**，前面的 `pay.` `login.` 全是烟雾弹
- 银行支付类自己输网址/用官方 App，不点短信群链接；红色警告别手痒点"仍要继续"

**② 让软件盯**
- 浏览器安全黑名单（Google Safe Browsing 等）：访问诈骗站全屏红警
- 密码管理器：只在真域名自动填充——**假网站上它不肯自动填，本身就是红灯**！
- 国家反诈中心 App

**③ 行业机制**
- CA 分级：银行类要组织级审查（营业执照+电话回访）
- 大厂买光相似域名（gogle/google/goog1e...）
- 快速举报下架

### 本质

> 技术上域名是**逐字符精确比对**，人眼却是"看着像"就行——这条缝就是钓鱼的全部生存空间。
> 别信"看着像"，只信"查证过"。

钓鱼和中间人是孪生兄弟：中间人攻"路上"（证书体系防），钓鱼攻"起点"（认域名+黑名单防）。

## 八、一句话总结合集

1. 证书 = CA 盖章的「身份+公钥」担保书，明文可读，附一个私钥锁的指纹盒
2. 指纹机（哈希）= 单向榨汁机，无钥匙不可逆，专治篡改
3. 签名 = 用自己私钥锁指纹，全世界用你的公钥验
4. 验证 = 对比 A（厂家封存的快照）和 B（现场重算的快照）
5. 信任链 = 沿着签名一层层爬，爬到系统预装的根为止
6. 根证书 = 出厂焊死在 `/system/etc/security/cacerts/` 里的离线信任基石
7. 中间人 = 两面派，让双方都跟它加密
8. Pinning = 自家保安复核编号，标准安检骗不过它
9. 绕过 Pinning = frida 当内鬼，关校验+伪造返回值
10. 小锁 🔒 = 它是它 ≠ 它不坑你
